# K PLUS · First Jobber — ต้นแบบ Full Stack

ต้นแบบฟีเจอร์ใหม่บน K PLUS สำหรับกลุ่ม **First Jobber** (เด็กจบใหม่ ทำงานปีแรก)
ช่วยให้บริหารเงินและเก็บออมได้ดีขึ้น และลดความเสี่ยงจาก Scam / Fraud

มีทั้ง **หน้าบ้าน (แอปมือถือ)** และ **หลังบ้าน (Ops Console)** โดยข้อมูลทุกอย่างถูกเขียนลงฐานข้อมูลจริง
รายงานหลังบ้านคำนวณสดจากพฤติกรรมที่เกิดขึ้นจริงในแอป ไม่ใช่ตัวเลขที่ hard-code ไว้

---

## วิธีรัน

ไม่ต้องติดตั้ง dependency ใด ๆ (ใช้ Node.js ล้วน ต้องการ Node 18+)

```bash
cd kplus-firstjobber && npm run seed && npm start
```

| ส่วน | URL | หมายเหตุ |
|---|---|---|
| หน้าบ้าน (แอป) | http://localhost:4173/ | เลือกโปรไฟล์ผู้ใช้เพื่อเข้าใช้งาน |
| หลังบ้าน (Ops) | http://localhost:4173/admin | รหัสผ่าน `kplus2026` |

`npm run seed` จะล้างและสร้างข้อมูลตั้งต้นใหม่ (ผู้ใช้ 5 คน + ประวัติ 2 รอบเงินเดือน + เคสมิจฉาชีพ)

## ฟีเจอร์ตาม requirement

### กลุ่มที่ 1 — ช่วยบริหารเงินและเก็บออม

**1. Safe-to-Spend** — หน้าแรกไม่ได้โชว์แค่ "ยอดคงเหลือ"
เพิ่มตัวเลข **"วันนี้ควรใช้ได้ไม่เกินเท่าไหร่"** ที่หักบิลที่ยังไม่ตัดและเงินสัปดาห์ถัดไปที่กันไว้แล้ว

```
Safe-to-Spend = ยอดคงเหลือ − บิลที่ยังไม่ตัดในรอบนี้ − เงินซองสัปดาห์ถัดไป
วันนี้ควรใช้   = เงินในซองสัปดาห์นี้ที่เหลือ ÷ จำนวนวันที่เหลือในสัปดาห์
```

พร้อมสถานะ `ตามแผน / ต่ำกว่าแผน / ใช้เกินแผน` เทียบกับอัตราการใช้ที่ควรเป็น ณ วันนั้น

**2. K Pockets** — วันเงินเดือนเข้า ระบบตัดอัตโนมัติเป็น 2 ซอง แล้วแตกซองที่ 2 เป็น 4 สัปดาห์
ตรงตามตัวอย่างในโจทย์ (เงินเดือน 20,000 → Fix 5,000 / เหลือ 15,000 → สัปดาห์ละ 3,750 × 4)
แก้แผนเงินเดือน/ค่าคงที่/วันเงินเดือนออกได้

**ย้ายเงินระหว่างซอง + ประวัติย้อนหลัง** — สัปดาห์ไหนมีรายจ่ายพิเศษก็ยืมจากสัปดาห์หน้ามาก่อนได้
ทุกครั้งจะถูกบันทึกเป็นประวัติ พร้อม **เหตุผล** (เลือกจาก chip หรือพิมพ์เอง) และยอดคงเหลือของซองต้นทาง ณ ตอนนั้น
เพื่อให้ย้อนดูได้ว่า "เงินหายไปไหน" — ดูได้ที่การ์ด *ประวัติการย้ายเงินระหว่างซอง* ในหน้าซองเงิน
เมื่อย้ายเสร็จ ยอด "วันนี้ควรใช้" จะถูกคำนวณใหม่ทันที (ทดสอบแล้ว: ย้าย 300 บาทเข้าสัปดาห์ปัจจุบัน → 122.60 เป็น 182.60)
ระบบกันไม่ให้ย้ายเกินเงินที่เหลือในซองต้นทาง และไม่ให้เลือกซองต้นทาง/ปลายทางซ้ำกัน

**3. Round-up** — จ่าย 48 ปัดเป็น 50 ส่วนต่าง 2 บาทเข้ากองทุนออมอัตโนมัติ
เปิด/ปิดได้ และเลือกขั้นการปัดได้ (10 / 20 / 50 / 100 บาท)

**4. First Jobber Score** — วัดสุขภาพการเงิน 5 ด้าน ถ่วงน้ำหนักเป็นคะแนน 0–100

| ด้าน | น้ำหนัก | วัดจาก |
|---|---|---|
| วินัยการออม | 25% | เงินออมในรอบ ÷ เงินเดือน (เป้า 20%) |
| คุมงบรายสัปดาห์ | 25% | ซองที่ผ่านมาไม่บานปลาย + ซองปัจจุบัน |
| จ่ายบิลตรงเวลา | 20% | บิลประจำถูกตัดครบตามรอบ |
| เงินสำรองฉุกเฉิน | 15% | เงินออม ÷ รายจ่ายต่อเดือน (เป้า 3 เดือน) |
| ภูมิคุ้มกันภัยการเงิน | 15% | ใช้ Scam Radar สม่ำเสมอ และไม่ฝืนโอนเข้าบัญชีเสี่ยง |

คะแนนแปลงเป็นระดับ Bronze / Silver / Gold / Platinum → **ดอกเบี้ยเงินฝากขั้นบันไดและวงเงินสินเชื่อที่ดีขึ้น**

**5. Tax Coach ปีแรก** — คำนวณภาษีจากเงินเดือนจริง โดยนับเฉพาะเดือนที่มีรายได้ (คนเริ่มงานกลางปี)
หักค่าใช้จ่าย 50% (เพดาน 100,000) + ลดหย่อนส่วนตัว 60,000 + ประกันสังคม + ประกันชีวิต + เลี้ยงดูบิดามารดา
แล้วเทียบ 4 สถานการณ์การซื้อกองทุนลดหย่อน พร้อมปุ่ม **คลิกเดียวซื้อทั้งตะกร้า** (ThaiESG / SSF / RMF)

> หมายเหตุด้านความถูกต้อง: ระบบ **ไม่** แนะนำให้ซื้อจนภาษีเป็น 0 เสมอไป
> เพราะคนเพิ่งเริ่มทำงานอาจต้องใช้เงิน 65,000 เพื่อประหยัดภาษีเพียง 3,250 บาท
> คำแนะนำจริงจึงถูกจำกัดไว้ที่ไม่เกิน 15% ของรายได้ทั้งปี และแสดง % ที่ได้คืนต่อเงินที่ลงทุนให้เห็นชัด
> ปีแรกที่ทำงานไม่ครบปีมักได้ภาษี 0 บาท — ระบบจะบอกตรง ๆ และประมาณการปีถัดไปให้แทน

### กลุ่มที่ 2 — ป้องกัน Scam และ Fraud

**6. Scam Radar** — ก่อนโอน บอก **อายุบัญชีปลายทาง** และ **ประวัติการถูกรายงาน** พร้อมคะแนนความเสี่ยง 0–100

| ปัจจัย | น้ำหนัก |
|---|---|
| บัญชีเปิดใหม่ < 7 วัน / < 30 วัน / < 6 เดือน | +45 / +30 / +10 |
| ถูกรายงานยืนยันแล้ว ≥ 5 / ≥ 2 / 1 ครั้ง | +55 / +35 / +20 |
| อยู่ในบัญชีดำหน่วยงานรัฐ | +60 |
| เข้าข่ายบัญชีม้า (เงินเข้า-ออกเร็วผิดปกติ) | +30 |
| ยอดสูงผิดปกติ / โอนดึก / โอนครั้งแรก | +10 / +8 / +8 |
| ร้านค้ายืนยันตัวตนกับธนาคาร | −30 |

ระดับ: `ปลอดภัย (0–19) → ควรระวัง (20–44) → เสี่ยงสูง (45–69) → อันตราย (70–100)`
เมื่อความเสี่ยง ≥ 45 ปุ่ม **"ยกเลิกการโอน"** จะกลายเป็นปุ่มหลัก และปุ่มโอนต่อถูกลดความเด่นลง
การกดยกเลิกจะถูกบันทึกเป็น "ความเสียหายที่ป้องกันได้" ในรายงานหลังบ้าน

**7. Report บัญชี** — ทุกครั้งที่โอนเงินสามารถรายงานบัญชีได้ ระบบออกเลขเคส (`KSR-YYYYMM-NNNN`)
ส่งต่อศูนย์รับแจ้งเหตุภัยทางการเงิน แล้วเก็บเป็นประวัติที่ **แสดงใน Scam Radar ของผู้ใช้คนอื่นทันทีที่เจ้าหน้าที่ยืนยัน**

## วงจรข้อมูลจริง (จุดสำคัญของต้นแบบนี้)

```
ผู้ใช้ A เจอมิจฉาชีพ → กดรายงานบัญชีในแอป  (สถานะ pending)
        ↓
หลังบ้าน: เจ้าหน้าที่เปิดเคส → กด "ยืนยันว่าเป็นบัญชีเสี่ยง" (+ ขึ้น blacklist)
        ↓
ผู้ใช้ B กำลังจะโอนเข้าบัญชีเดียวกัน → Scam Radar เตือนแรงขึ้นทันที
        ↓
ผู้ใช้ B กดยกเลิก → บันทึกเป็น "ความเสียหายที่ป้องกันได้" ในรายงานหลังบ้าน
```

ทดสอบวงจรนี้ได้จริง: เปิดแอปรายงานบัญชีหนึ่ง → ไปหลังบ้านกดยืนยัน → กลับมาตรวจบัญชีเดิมอีกครั้ง คะแนนเสี่ยงจะเปลี่ยน

## หลังบ้าน (Ops Console)

- **ภาพรวม** — KPI 6 ตัว, กราฟเงินออมจาก Round-up รายวัน, กราฟการตรวจบัญชีรายวัน,
  สัดส่วนระดับความเสี่ยง, คะแนนเฉลี่ย 5 ด้าน, การกระจายระดับผู้ใช้, ประเภทการหลอกลวง, หมวดค่าใช้จ่าย, กิจกรรมล่าสุด
- **ผู้ใช้ First Jobber** — สุขภาพการเงินรายคน คะแนน ระดับ อัตราการออม สถานะการใช้จ่าย
- **คิวตรวจสอบรายงาน** — เปิดเคส ดูรายละเอียด กดยืนยัน/ปฏิเสธ พร้อมขึ้น blacklist
- **บัญชีเฝ้าระวัง** — อันดับบัญชีเสี่ยง และฟอร์มเพิ่มข้อมูลบัญชีจากหน่วยงานภายนอก
- **ข้อมูล / ส่งออก** — ดาวน์โหลด CSV (รองรับภาษาไทยใน Excel) 5 ชุด + สรุปผลลัพธ์โปรแกรม

## โครงสร้างโค้ด

```
kplus-firstjobber/
├── server/
│   ├── index.js    HTTP server + REST API (ไม่มี dependency)
│   ├── logic.js    โดเมนล้วน: cycle, pockets, safe-to-spend, round-up, score, tax, risk
│   ├── service.js  ชั้นบริการฝั่งผู้ใช้ อ่าน/เขียนฐานข้อมูล
│   ├── admin.js    รายงานหลังบ้าน + คิวตรวจสอบ + export CSV
│   ├── db.js       ฐานข้อมูล JSON เขียนลงดิสก์จริง (atomic write)
│   └── seed.js     ข้อมูลตั้งต้นสมจริง 2 รอบเงินเดือน
├── public/
│   ├── index.html  แอปหน้าบ้าน
│   ├── admin.html  Ops Console
│   ├── css/        app.css (มือถือ) · admin.css (เดสก์ท็อป + dark mode)
│   └── js/         app.js · admin.js
└── data/db.json    ข้อมูลจริงทั้งหมด (สร้างอัตโนมัติ)
```

### API หลัก

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| GET | `/api/state?userId=` | สถานะรวมของหน้าแรก (ซอง, safe-to-spend, คะแนน, round-up) |
| POST | `/api/expense` | บันทึกค่าใช้จ่าย + ทำ round-up |
| POST | `/api/pockets/move` | ย้ายเงินระหว่างซอง (บันทึกประวัติ + เหตุผล) |
| GET | `/api/pockets/moves?userId=` | ประวัติการย้ายซองย้อนหลัง |
| POST | `/api/tax/preview` · `/api/tax/buy` | คำนวณภาษี · ซื้อตะกร้ากองทุน |
| POST | `/api/radar/check` | ตรวจบัญชีปลายทาง |
| POST | `/api/transfer` · `/api/transfer/abort` | โอน · ยกเลิกหลังเห็นคำเตือน |
| POST | `/api/reports` | รายงานบัญชีมิจฉาชีพ |
| GET | `/api/admin/overview` | รายงานหลังบ้านทั้งหมด (ต้องมี token) |
| POST | `/api/admin/reports/review` | ยืนยัน/ปฏิเสธเคส |
| GET | `/api/admin/export/{users\|reports\|checks\|moves\|transactions}.csv` | ส่งออก CSV |

## ขอบเขตของต้นแบบ

- เป็น prototype เพื่อสาธิตแนวคิด ไม่ได้เชื่อมต่อ core banking จริง การโอน/ซื้อกองทุนเป็นการจำลอง
- การเข้าสู่ระบบฝั่งผู้ใช้เป็นการเลือกโปรไฟล์ (ไม่มีรหัสผ่าน) ฝั่งหลังบ้านใช้รหัสผ่านเดียวแบบง่าย
- ข้อมูลบัญชีมิจฉาชีพทั้งหมดเป็นข้อมูลสมมติ เลขบัญชีไม่ใช่ของจริง
- ตัวเลขภาษีอ้างอิงเกณฑ์ลดหย่อนมาตรฐาน ใช้ประกอบการตัดสินใจเบื้องต้น ไม่ใช่คำแนะนำทางภาษีอย่างเป็นทางการ
